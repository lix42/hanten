Q1 — does a Display P3 canvas show P3 colours unclipped?


Each pair: left half is the P3 primary, right half the sRGB primary (the most
saturated colour sRGB can hold). On a P3 display the halves differ — the left is more
saturated. On an sRGB display, or if the canvas clips to sRGB, they look the same. The CSS
row is the reference: WebKit's CSS is known to honour color(display-p3 …).

Q2 — can an HDR preview be shown?


Synthetic patches: in each pair the left is reference white (1.0), the right
2× or 4× it; the ramp runs 0→4× with ticks at 1, 2 and 3. If HDR works, the right patches
are brighter than the left, and the ramp keeps brightening past the first tick. If clamped,
the pairs look identical and the ramp goes flat at the first tick. Judge on the XDR
display, with brightness not at maximum.

Q3 — slider to drawn frame, with real renders


Needs the Tauri shell. Open the frame, then drag a slider, or run the scripted
sweep (one input per animation frame for 3 seconds). "Coalesce" keeps one request in flight
and sends only the newest value when it returns; "every input" sends each event, and the
core skips any request older than the newest.



  
  
  
  




  
  
  
  
  
  
  
  








Q4 — the canvas against the exported file


After a render at default sliders, "Check readback" reads the canvas back
in display-p3 and compares it with the bytes that were put (the factor-1 preview equals the
export at 8 bits; see the report). Then open sdr.tif in Preview beside this
window and compare by eye.
