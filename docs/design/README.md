# Design documents

Where a new design document goes. The existing ones — `docs/design-spec.md` (the
authoritative Step-1 design) and `docs/design-update.md` (the reconstruction/rendering
redesign) — stay at `docs/` for now: both are cited from CLAUDE.md, `src/` doc comments
and many task files, and moving them would rot references for no gain.

A design document says what the system should do and why. It is not a task (that is
`docs/tasks/`), not an execution log (`docs/progress/`), not a measurement
(`docs/reports/`) and not the answer to an open question (`docs/spike/`).
